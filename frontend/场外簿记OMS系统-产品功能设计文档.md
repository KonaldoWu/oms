## 一、平台概述

### 1.1 平台定位

场外簿记OMS系统（Order Management System）是面向金融机构场外衍生品业务的一体化簿记与订单管理平台，覆盖从投资研究、产品入池、交易执行、风控审批、财务核算到报表输出的全生命周期管理。

### 1.2 核心价值

- **统一簿记**：将场外交易的计划书管理、产品管理、对手方管理集中在一个平台，消除信息孤岛
- **流程闭环**：从投资计划书提交到ERP流程完成，全流程可追溯、可审计
- **财务直连**：会计凭证自动生成、XML格式转换、一键推送NC财务系统，减少人工操作
- **实时监控**：首页仪表盘实时展示持仓、产品、凭证、邮件解析等核心业务指标

### 1.3 用户角色 【完善】

| 角色 | 职责 | 默认落地页 |
|------|------|-----------|
| 投资经理 | 发起投资计划书、管理产品池、发起交易 | 首页（业务总览） |
| 交易员 | 执行交易、录入对手方 | 交易管理 |
| 部门领导 | 审批投资计划书、对手方入池审批 | 对手方管理 |
| 财务人员 | 凭证审核、NC系统推送 | 审批中心（财务审核） |
| 部门风控 | 产品入池审批、交易风控审批 | 审批中心 |
| 公司领导 【新增】 | 查看全公司所有业务数据，用于高管决策和监督 | 首页（业务总览） |

## 三、核心工作流程

### 3.1 投资交易全流程

```
1. 投资经理上传投资计划书（PDF/Word）
       │
       ▼
2. 系统解析计划书，提取产品列表和额度分配
       │
       ▼
3. 投资经理选择交易员，提交审批
       │
       ▼
4. 审批中心进入「投资计划书审批」流程：
   投资经理提交 → 部门负责人审批 → 风控审批 → 总经理审批
       │
       ▼ (全部通过)
5. 计划书状态变更为「已通过」，关联产品可发起交易
       │
       ▼
6. 投资经理在产品列表中发起交易，输入投资金额
       │
       ▼
7. 审批中心进入「交易审批」流程：
   投资经理提交 → 风控审批 → 财务确认 → 交易执行
       │
       ▼ (财务确认后)
8. 系统自动生成会计凭证（待确认状态）
       │
       ▼
9. 财务人员在审批中心「财务审核」中确认凭证
       │
       ▼
10. 凭证转换为NC系统XML格式
       │
       ▼
11. 一键推送至NC财务系统，流程完结
```

### 3.2 产品入池流程

```
1. 投资经理提交产品入池申请
       │
       ▼
2. 审批中心进入「产品入池审批」流程：
   投资经理提交 → 风控审批 → 产品入池生效
       │
       ▼ (通过)
3. 产品状态变更为「在池」，可在交易管理中发起交易
```

### 3.3 对手方入池流程

```
1. 交易员/投资经理提交对手方入池申请（含用资计划书）
       │
       ▼
2. 审批中心进入「对手方入池审批」流程：
   交易员提交 → 风控审批 → 合规审批 → 对手方入池生效
       │
       ▼ (通过)
3. 对手方可用于交易
```

### 3.4 财务核算流程

```
交易成交/产品净值变更/兑息兑付
       │
       ▼
系统自动生成会计凭证（状态：待确认）
       │
       ▼
财务人员审核凭证（可编辑借方/贷方科目、金额）
       │
       ▼
确认凭证（状态：已确认）
       │
       ▼
转换为NC系统XML格式
       │
       ▼
推送至NC财务系统（状态：已推送NC）
```

### 4.1 首页（业务总览）【完善】

#### 4.1.1 模块定义 【完善】

首页是投资经理的日常工作台，以仪表盘形式实时展示核心业务指标，帮助投资经理快速掌握全局动态并处理紧急事项。

#### 4.1.1.1 模块定义补充 【新增】

- **核心职责**：聚合展示全平台关键业务指标的实时概览面板，提供待办事项入口和通知中心
- **边界范围**：首页仅负责数据展示与跳转引导，不承载任何数据编辑或审批操作

#### 4.1.1.2 核心交互流程 【新增】

1. 用户登录系统，默认进入首页
2. 系统根据用户角色加载对应指标卡片（投资经理看持仓/产品数据，公司领导看全量数据）
3. 用户点击指标卡片可跳转至对应模块详情页
4. 用户在"待审批事项"区域点击"去处理"跳转至审批中心
5. 用户在"通知中心"点击通知条目，跳转至对应业务处理页面

#### 4.1.1.3 边界条件 【新增】

- 首页不提供数据编辑功能，所有操作均跳转至对应模块
- 指标数据为实时聚合，不提供历史趋势回溯（趋势图表除外）
- 通知中心仅展示最近30天内的通知

#### 4.1.2 功能清单

| 功能 | 描述 |
|------|------|
| 核心指标概览 | 展示持仓总金额、在池产品数、今日凭证数、解析邮件数、NC推送成功率 |
| 业务趋势图表 | 近7日交易趋势、凭证生成与NC推送对比、邮件解析成功率、产品类型占比 |
| 待审批事项 | 列出待处理的投资计划书审批，支持跳转至审批中心 |
| 通知中心 | 分紧急/警告/正常三级展示系统通知，支持跳转处理 |

#### 4.1.3 指标字段定义

| 指标名称 | 计算规则 | 展示格式 |
|---------|---------|---------|
| 持仓总金额 | 所有在投产品的已投额度之和 | ¥XX,XXX,XXX |
| 在池产品数 | 产品池中状态为「在投」的产品数量 | 整数 |
| 今日生成凭证 | 当日系统自动生成的凭证数量 | 整数 |
| 解析邮件数 | 当日系统解析的邮件数量 | 整数 |
| NC推送成功率 | 已推送NC凭证数 / 已确认凭证数 × 100% | XX% |

### 4.2 交易管理 【完善】

#### 4.2.1 模块定义 【完善】

交易管理是投资计划书的全生命周期管理中心，负责计划书的创建、解析、审批提交、交易发起等核心业务操作。

#### 4.2.1.1 模块定义补充 【新增】

- **核心职责**：管理投资计划书的创建、解析、审批流转和交易发起，是投资经理与交易员的核心操作入口
- **边界范围**：交易管理负责计划书和交易的前端操作，审批逻辑由审批中心承接，财务核算由审批中心财务审核承接

#### 4.2.1.2 核心交互流程 【新增】

1. 投资经理点击"上传计划书"，选择PDF/Word文件上传
2. 系统解析计划书，提取产品列表和额度分配，展示解析结果
3. 投资经理确认解析结果，选择交易员，点击"提交审批"
4. 审批通过后，计划书状态变更为"已通过"，关联产品可发起交易
5. 投资经理在计划书详情中点击关联产品的"发起交易"按钮
6. 输入投资金额，提交交易审批
7. 交易审批通过后，进入ERP执行流程
8. 交易成交后，系统自动生成会计凭证

#### 4.2.1.3 边界条件 【新增】

- 计划书审批通过后，投资经理不可修改计划书内容，仅可发起交易
- 交易金额不可超过产品剩余可投额度
- 计划书"已完结"后不可再发起交易
- 交易员仅可查看和执行分配给自己的交易

#### 4.2.2 功能清单

| 功能 | 描述 |
|------|------|
| 计划书列表 | 展示所有投资计划书及其状态，支持展开查看关联产品 |
| 上传计划书 | 上传PDF/Word格式的投资计划书，系统解析提取产品信息 |
| 计划书审批 | 提交计划书进入审批流程 |
| 发起交易 | 对已通过计划书的关联产品发起交易，输入投资金额 |
| 交易记录 | 查看产品的历史交易记录 |
| 文件预览 | 在线预览计划书PDF文件（含水印） |

#### 4.2.3 数据实体与字段

**投资计划书**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 计划书编号 | 文本 | 是 | 系统自动生成，格式 TP+YYYYMMDD+序号 |
| 计划书名称 | 文本 | 是 | 计划书标题 |
| 关联产品 | 关联 | 是 | 关联的产品列表 |
| 总额度 | 金额 | 是 | 计划书总投资额度 |
| 已用额度 | 金额 | — | 已发起交易的累计金额 |
| 状态 | 枚举 | — | 待提交/审批中/已通过/已完结 |
| 创建人 | 用户 | — | 创建该计划书的投资经理 |
| 创建时间 | 时间 | — | 计划书创建时间 |
| 关联文件 | 附件 | 是 | 上传的计划书文件 |
| 交易员 | 用户 | 是 | 指定的交易执行人 |

**计划书关联产品**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 产品ID | 文本 | 是 | 产品池中的产品编号 |
| 产品名称 | 文本 | 是 | 产品名称 |
| 产品类型 | 枚举 | 是 | 权益类/固收类/混合型 |
| 计划额度 | 金额 | 是 | 分配给该产品的额度 |
| 已用额度 | 金额 | — | 该产品已发起交易的金额 |

#### 4.2.4 状态流转

```
待提交 ──提交审批──▶ 审批中 ──审批通过──▶ 已通过 ──额度用完──▶ 已完结
  │                    │
  │ 可编辑/删除        │ 可撤回
  ▼                    ▼
(编辑/删除)         (回到待提交)
```

### 4.3 资金管理 【完善】

#### 4.3.1 模块定义 【完善】

资金管理模块提供账户资金状态的实时监控与出入金记录查询，帮助管理人员掌握资金动态。

#### 4.3.1.1 模块定义补充 【新增】

- **核心职责**：监控账户资金余额与变动情况，记录出入金明细，为投资决策提供资金可用性参考
- **边界范围**：资金管理仅提供资金状态展示与记录查询，不执行实际的资金划拨操作

#### 4.3.1.2 核心交互流程 【新增】

1. 用户进入资金管理模块，查看资金概览卡片（账户余额、可用资金、冻结资金）
2. 用户切换"资金流水"标签页，按日查看余额变动记录
3. 用户切换"出入金记录"标签页，查看历史出入金明细
4. 用户可按日期范围筛选流水和出入金记录

#### 4.3.1.3 边界条件 【新增】

- 资金管理为只读模块，不提供资金操作功能
- 出入金记录由交易成交/兑息兑付等业务事件自动生成，不可手动新增
- 资金流水按日聚合，不展示日内明细

#### 4.3.2 功能清单

| 功能 | 描述 |
|------|------|
| 资金概览 | 展示账户余额、可用资金、冻结资金、今日出入金 |
| 资金流水 | 按日展示资金余额变动记录 |
| 出入金记录 | 展示历史出入金明细 |

#### 4.3.3 数据实体与字段

**资金流水**

| 字段 | 类型 | 说明 |
|------|------|------|
| 日期 | 日期 | 流水日期 |
| 余额 | 金额 | 当日账户总余额 |
| 可用资金 | 金额 | 可用于投资的资金 |
| 冻结资金 | 金额 | 因交易冻结的资金 |

**出入金记录**

| 字段 | 类型 | 说明 |
|------|------|------|
| 时间 | 时间 | 出入金时间 |
| 类型 | 枚举 | 入金/出金 |
| 金额 | 金额 | 出入金金额 |
| 状态 | 枚举 | 成功/失败 |
| 备注 | 文本 | 银行转账/提现等 |

### 4.4 产品管理 【完善】

#### 4.4.1 模块定义 【完善】

产品管理模块是产品池的核心管理入口，负责产品的创建、查询、状态管理和交易发起，同时支持产品净值追踪和收益分析。

#### 4.4.1.1 模块定义补充 【新增】

- **核心职责**：管理产品池的全生命周期，包括产品入池、信息维护、净值追踪、交易发起和产品状态流转
- **边界范围**：产品管理负责产品自身信息管理，对手方信息由对手方管理模块维护，合同管理由合同管理模块维护

#### 4.4.1.2 核心交互流程 【新增】

1. 投资经理在产品列表页查看所有产品，支持按状态/类型筛选
2. 投资经理点击"添加产品"填写产品信息，提交入池审批
3. 风控审批通过后，产品状态变更为"待投"或"在投"
4. 投资经理在产品列表点击"发起交易"，输入金额提交交易审批
5. 用户点击产品名称，进入产品详情页
6. 产品详情页展示基础信息、净值记录、收益率曲线、交易记录、ERP流程跟踪、变更日志

#### 4.4.1.3 边界条件 【新增】

- 产品入池需经过审批流程，不可直接入池
- 产品的投资经理和交易员字段在创建时指定，后续仅管理员可通过人员转移功能变更
- 产品净值通过邮件解析或手工录入更新，不可直接编辑历史净值
- 产品"已完结"后不可再发起交易

#### 4.4.2 功能清单

| 功能 | 描述 |
|------|------|
| 产品列表 | 展示产品池中所有产品，支持搜索与投资状态筛选 |
| 添加产品 | 风控角色可新增产品入池 |
| 编辑产品 | 风控角色可编辑产品基础信息 |
| 发起交易 | 对在池产品发起投资交易 |
| 收益周期切换 | 按本年/本月/昨日/自定义周期查看收益数据 |
| 产品详情跳转 | 点击产品名称进入产品详情页 |

#### 4.4.3 数据实体与字段

**产品**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 产品ID | 文本 | 是 | 唯一标识，如P0001 |
| 产品名称 | 文本 | 是 | 产品全称 |
| 投资状态 | 枚举 | 是 | 在投/待投/完结 |
| 最新净值日期 | 日期 | 是 | 最近一次净值更新日期 |
| 单位净值 | 数值 | 是 | 精度4位小数 |

| 产品描述 | 文本 | 否 | 产品说明 |

**净值历史记录**

| 字段 | 类型 | 说明 |

#### 4.7.1 模块定义 【完善】

审批中心是全平台的审批枢纽与财务核算中心，以Tab页形式整合「审批事项」和「财务审核」两大功能域，是部门领导、风控、财务人员的核心工作台。

#### 4.7.1.1 模块定义补充 【新增】

- **核心职责**：集中管理全平台所有审批事项（计划书、产品入池、对手方入池、交易审批）和财务核算流程（凭证确认、XML转换、NC推送）
- **边界范围**：审批中心负责审批流程的推进和凭证的财务处理，不负责业务数据的创建和编辑

#### 4.7.1.2 核心交互流程 【新增】

**审批事项流程：**
1. 用户进入审批中心，默认展示"审批事项"Tab
2. 页面顶部按审批类型展示分类统计卡片（待处理数量）
3. 用户点击统计卡片或使用筛选条件选择审批类型
4. 列表展示待审批事项，用户点击"审批"按钮
5. 弹窗展示审批详情和流程时间线
6. 用户点击"通过"推进至下一步，或点击"驳回"（需填写原因）终止审批
7. 全部步骤通过后，审批状态变更为"已通过"

**财务审核流程：**
1. 用户切换至"财务审核"Tab
2. 页面展示统计概览（待审核、已确认、已推送NC数量）
3. 用户在列表中找到待确认的凭证，点击"查看凭证"
4. 核对借方/贷方科目和金额，必要时编辑
5. 点击"确认凭证"，凭证状态变更为"已确认"
6. 点击"转换XML"，将凭证转换为NC格式
7. 点击"推送NC"，一键推送至NC财务系统

#### 4.7.1.3 边界条件 【新增】

- 审批流程按步骤顺序推进，不可跳步
- 审批驳回为终态，不可恢复，需重新发起
- 会计凭证在"待确认"状态下可编辑，确认后不可修改
- 已推送NC的凭证不可再次推送
- 驳回操作必须填写驳回原因

#### 4.8.1.1 模块定义补充 【新增】

- **核心职责**：管理系统用户账号的增删改查、角色分配、投资组分配、账号停用与资产所有权转移
- **边界范围**：用户管理负责账号和权限层面的管理，不涉及业务数据的操作权限之外的逻辑

#### 4.8.1.2 核心交互流程 【新增】

1. 管理员进入用户管理模块，查看用户列表
2. 点击"新增用户"，填写用户名、姓名、选择角色
3. 根据角色显示可分配的投资组多选列表（详见4.8.4投资组分配规则）
4. 选择投资组后保存，用户账号创建完成
5. 管理员可编辑用户信息、调整角色和投资组分配
6. 管理员可对用户执行"账号停用与资产转移"操作（详见4.8.5账号停用与资产所有权转移）

#### 4.8.1.3 边界条件 【新增】

- 用户管理仅系统管理员可操作
- 同一用户不可分配互斥角色（如投资经理与部门风控不可兼任）
- 用户禁用后立即失去系统访问权限
- 已停用账号不可恢复

#### 4.8.4 投资组与角色分配机制 【新增】

##### 4.8.4.1 投资组概念定义

投资组（Investment Group）是按业务部门划分的投资管理单元，用于隔离不同业务线的产品、计划书和交易数据，实现精细化的数据权限控制。

##### 4.8.4.2 投资组枚举

| 投资组编码 | 投资组名称 | 说明 |
|-----------|-----------|------|
| IG_ZH | 专户投资组 | 专户类投资业务 |
| IG_XN | xn账户 | xn账户相关投资业务 |
| IG_FB | fb账户 | fb账户相关投资业务 |
| IG_LC | 理财投资组 | 理财类投资业务 |
| IG_QY | 权益投资组 | 权益类投资业务 |

##### 4.8.4.3 角色按组分配规则

| 角色 | 按组分配 | 分配规则 | 数据范围 |
|------|---------|---------|---------|
| 投资经理 | 是 | 必须分配到至少一个投资组 | 只能操作该组下的产品和计划书 |
| 交易员 | 是 | 必须分配到至少一个投资组 | 只能执行该组下的交易 |
| 部门风控 | 否（按部门） | 分配到部门 | 可查看本部门所有投资组的审批事项 |
| 部门领导 | 否（按部门） | 分配到部门 | 可审批本部门所有投资组的事项 |
| 财务人员 | 否 | 不按组分配 | 可查看全部财务数据 |
| 公司领导 | 否 | 不按组分配 | 可查看全部内容 |

##### 4.8.4.4 投资组分配界面

用户编辑页面中，根据用户角色动态显示投资组分配区域：

- **投资经理/交易员**：显示投资组多选列表，至少选择一个投资组，保存时校验
- **部门风控/部门领导**：显示部门选择下拉框，不显示投资组选择
- **财务人员/公司领导**：不显示投资组和部门选择区域

**投资组多选列表交互：**
1. 以Checkbox Group形式展示5个投资组选项
2. 默认不选中，用户需手动勾选
3. 保存时校验：投资经理和交易员至少选中1个投资组，否则提示"请至少选择一个投资组"
4. 编辑时回显已分配的投资组，支持增减

#### 4.8.5 账号停用与资产所有权转移 【新增】

##### 4.8.5.1 账号停用与资产转移流程

1. 管理员在用户列表中选择目标用户，点击"账号停用与资产转移"
2. 系统检测该用户名下的在管资源：
   - **作为投资经理**：名下所有在投/待投产品、未完结计划书
   - **作为交易员**：名下所有待执行/执行中交易、与投资经理的关联关系
3. 系统展示资源清单，管理员选择接收人（必须同角色同投资组）
4. 确认转移后：
   - 产品的投资经理/交易员字段更新为接收人
   - 计划书的创建人/交易员字段更新为接收人
   - 交易的交易员字段更新为接收人
   - 产品详情页的变更日志记录转移操作
5. 用户状态变更为"已停用"，账号不可登录但数据保留

##### 4.8.5.2 接收人选择规则

- 接收人必须与停用账号用户角色相同（投资经理→投资经理，交易员→交易员）
- 接收人必须与停用账号用户有至少一个共同投资组
- 接收人账号状态必须为"启用"
- 可按投资组分别选择不同的接收人

##### 4.8.5.3 转移记录字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 转移编号 | 文本 | 格式 TRF+YYYYMMDD+序号 |
| 转移类型 | 枚举 | 产品转移/计划书转移/交易转移 |
| 原负责人 | 用户 | 停用账号用户 |
| 新负责人 | 用户 | 接收人员 |
| 关联对象ID | 文本 | 被转移的产品/计划书/交易ID |
| 转移时间 | 时间 | 操作时间 |
| 操作人 | 用户 | 执行转移的管理员 |

##### 4.8.5.4 产品详情页变更日志记录格式

转移操作在产品详情页的变更日志中记录为：

```
【人员转移】投资经理由[原姓名]变更为[新姓名]，原因：账号停用，操作人：[管理员]
【人员转移】交易员由[原姓名]变更为[新姓名]，原因：账号停用，操作人：[管理员]
```

## 九、资产类型与流程状态 【新增】

### 9.1 概述

不同资产类型在产品生命周期、交易方式、到期处理和财务核算等方面存在差异。本章梳理各类型资产的完整流程状态，明确差异点，指导系统功能实现。

### 9.2 ABS（中保登）资产流程

#### 9.2.1 完整流程

```
产品入池(需对手方) → 计划书关联 → 交易发起(买入开仓) → 交易审批 → ERP执行 → 成交确认 → 
持有期(净值更新/公允价值变动) → 到期前3天预警 → 到期兑付 → 赎回/到期清算 → 
财务核算(凭证生成→确认→推送NC) → 生命周期完结
```

#### 9.2.2 状态定义

| 状态 | 说明 |
|------|------|
| 待投 | 产品已入池，尚未发起交易 |
| 在投 | 已有交易成交，产品处于持有期 |
| 已到期 | 产品到期日已过，尚未完成清算 |
| 清算中 | 产品进入清算流程 |
| 已完结 | 清算完成，生命周期结束 |

#### 9.2.3 状态流转

```
待投 ──交易成交──▶ 在投 ──到期日到达──▶ 已到期 ──发起清算──▶ 清算中 ──清算完成──▶ 已完结
                                        │                    │
                                        │ 到期兑付完成         │ 赎回
                                        ▼                    ▼
                                     已完结               已完结
```

### 9.3 信托资产流程

#### 9.3.1 完整流程

```
产品入池(需对手方+到期日) → 计划书关联 → 交易发起 → 交易审批 → ERP执行 → 成交确认 →
持有期(净值更新/兑息兑付) → 到期前3天预警 → 到期兑付 → 赎回/到期清算 →
财务核算 → 生命周期完结
```

#### 9.3.2 状态定义

| 状态 | 说明 |
|------|------|
| 待投 | 产品已入池，尚未发起交易 |
| 在投 | 已有交易成交，产品处于持有期 |
| 已到期 | 产品到期日已过，尚未完成清算 |
| 清算中 | 产品进入清算流程 |
| 已完结 | 清算完成，生命周期结束 |

#### 9.3.3 状态流转

```
待投 ──交易成交──▶ 在投 ──到期日到达──▶ 已到期 ──发起清算──▶ 清算中 ──清算完成──▶ 已完结
                                        │                    │
                                        │ 到期兑付完成         │ 赎回
                                        ▼                    ▼
                                     已完结               已完结
```

### 9.4 专户资管产品流程

#### 9.4.1 完整流程

```
产品入池(无到期日) → 计划书关联 → 交易发起(买入/赎回) → 交易审批 → ERP执行 → 成交确认 →
持有期(净值更新/公允价值变动/兑息兑付) → 主动赎回 →
财务核算 → 生命周期完结
```

#### 9.4.2 状态定义

| 状态 | 说明 |
|------|------|
| 待投 | 产品已入池，尚未发起交易 |
| 在投 | 已有交易成交，产品处于持有期 |
| 完结 | 主动赎回完成，生命周期结束 |

#### 9.4.3 状态流转

```
待投 ──交易成交──▶ 在投 ──主动赎回完成──▶ 完结
```

> 注：专户资管产品无到期日，不存在"已到期"和"清算中"状态。

### 9.5 碳金融资产流程

#### 9.5.1 完整流程

```
产品入池(需到期日) → 计划书关联 → 交易发起 → 交易审批 → ERP执行 → 成交确认 →
持有期(净值更新) → 到期前3天预警 → 到期/清算 →
财务核算 → 生命周期完结
```

#### 9.5.2 状态定义

| 状态 | 说明 |
|------|------|
| 待投 | 产品已入池，尚未发起交易 |
| 在投 | 已有交易成交，产品处于持有期 |
| 已到期 | 产品到期日已过，尚未完成清算 |
| 清算中 | 产品进入清算流程 |
| 已完结 | 清算完成，生命周期结束 |

#### 9.5.3 状态流转

```
待投 ──交易成交──▶ 在投 ──到期日到达──▶ 已到期 ──发起清算──▶ 清算中 ──清算完成──▶ 已完结
```

> 注：碳金融资产不可赎回，仅能到期清算。

### 9.6 各类型资产差异对比

| 维度 | ABS(中保登) | 信托 | 专户资管 | 碳金融 |
|------|------------|------|---------|-------|
| 对手方 | 必填 | 必填 | 选填 | 选填 |
| 到期日 | 必填 | 必填 | 无 | 必填 |
| 可赎回 | 是 | 是 | 是 | 否 |
| 兑息兑付 | 是 | 是 | 是 | 否 |
| 公允价值变动 | 是 | 是 | 是 | 是 |
| 到期预警 | 是 | 是 | 否 | 是 |
| 科目映射 | 11010109xx | 11010107xx | 11010107xx | 11010107xx |
| 交易方式 | 买入开仓 | 买入 | 买入/赎回 | 买入 |
| 到期处理 | 兑付/清算 | 兑付/清算 | 主动赎回 | 到期清算 |
| 生命周期状态数 | 5（待投/在投/已到期/清算中/已完结） | 5（待投/在投/已到期/清算中/已完结） | 3（待投/在投/完结） | 5（待投/在投/已到期/清算中/已完结） |

### 9.7 到期预警机制 【新增】

| 资产类型 | 是否支持到期预警 | 预警时机 | 预警方式 |
|---------|----------------|---------|---------|
| ABS(中保登) | 是 | 到期日前3天 | 首页通知中心（警告级别）+ 产品详情页提示 |
| 信托 | 是 | 到期日前3天 | 首页通知中心（警告级别）+ 产品详情页提示 |
| 专户资管 | 否 | — | — |
| 碳金融 | 是 | 到期日前3天 | 首页通知中心（警告级别）+ 产品详情页提示 |

预警通知内容格式：
```
【到期预警】产品[产品名称]将于[到期日期]到期，请及时处理到期兑付或清算事宜。
```
